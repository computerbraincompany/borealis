## Findings considered and rejected (do not re-audit without new evidence)

- **DuckDB `/query` can read server-local files** (e.g. `SELECT * FROM
  read_csv('/etc/passwd')` passes the SELECT/DDL validator in
  `python/app/datasets.py:149-170`) — real gap, but for a self-hosted
  single-tenant local app the authenticated caller is the dataset owner; the
  agent is the only other caller, and querying is its core function. The
  fix (function blocklist) risks breaking legitimate DuckDB queries. Deferred;
  revisit if the service is ever exposed beyond localhost or multi-tenant.
- **echarts 5.x XSS advisory** (GHSA-fgmj-fm8m-jvvx, moderate) — chart data
  is LLM-authored and rendered client-side in an already-trusted page; the
  web audit also flags a dev-server esbuild advisory. Both are lower signal
  than the server-side findings; revisit at next dependency bump (echarts 6
  is breaking).
- **xlsx npm package is abandoned with HIGH advisories (prototype pollution,
  ReDoS) and no npm fix** — used only for text-extraction of .xlsx uploads in
  `server/src/ingest.ts`. A swap (exceljs or the SheetJS CDN distribution)
  deserves its own plan; not bundled here because it changes parsing behavior
  and deserves a dedicated verification pass.
- **Perf: DuckDB re-reads every dataset file on every query/describe**
  (`python/app/datasets.py:_connection`) — the current design is deliberate
  (fresh in-memory connection per query avoids thread-safety issues). Worth a
  dedicated plan (persistent catalog/cached connections) but that is a real
  refactor with concurrency risk; not bundled here.
- **No automated tests anywhere** (no pytest, no vitest, no jest) —
  recommended follow-up plan: add pytest for the Python service (SQL
  validator, charts normalization, report builder escaping + footer counts)
  and vitest for the server tool loop + auth, using the asserts ported from
  plans 004/007. Not planned this pass because every plan above has a
  machine-checkable probe; the test baseline is the next investment.
