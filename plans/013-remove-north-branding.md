## Why this matters

The product is named **Borealis**. The working name "North" (from the upstream
Cohere North product it was cloned from) still leaks in user-visible surfaces:
the agent's system prompt makes the model call itself "North", chat/sources/
reports empty states address "North", the sidebar and auth page credit
"Cohere North", and generated HTML reports carry a "Generated by North" pill
and a "North Report" default title. Infrastructure identifiers (DB creds, API
key, env vars, package names) still say north too. None of these may ship.

## Changes

### Phase A — user-visible strings (safe, do first)
1. `agent.ts`: `You are North,` → `You are Borealis,`.
2. All web strings in table A: replace `North` → `Borealis`. For the two
   `Cohere North · …` subtitles use `ask your data · open source` (Shell)
   and `ask your data · open-source MVP` (AuthPage).
3. `reports.py`: `North Report` → `Borealis Report`; `Generated by North` →
   `Generated by Borealis`.
4. `main.py`: FastAPI title → `Borealis Report Service`; docstring → `Borealis report service — …`.
5. `index.ts`: boot log → `Borealis server listening on :…`.

### Phase B — identifiers (lockstep, no compat shims except env var)
6. `NORTH_STORAGE_DIR` → `BOREALIS_STORAGE_DIR`, reading the old name as
   fallback: `os.environ.get("BOREALIS_STORAGE_DIR") or os.environ.get("NORTH_STORAGE_DIR") or default`
   in both `main.py` and `datasets.py`. Update README + AGENTS.md mentions.
7. `pyproject.toml`: name → `borealis-report-service`, description → `Borealis analysis…`;
   regenerate lock: `cd python && uv lock && uv sync`.
8. `server/package.json`: name → `borealis-server`; refresh lock:
   `cd server && npm install --package-lock-only`.
9. `sk-north-local` → `sk-borealis-local` in ALL FOUR places at once
   (`litellm.yaml`, `server/.env`, `server/.env.example`, `config.ts` default).
   These must change together or the server can't authenticate to LiteLLM.
10. `config.ts:22` default `DATABASE_URL` → `postgres://borealis:borealis_password@localhost:5433/borealis`.

### Phase C — infrastructure (DATA-BEARING — read before executing)
11. `docker-compose.yml`: `borealis-postgres`, `POSTGRES_USER: borealis`,
    `POSTGRES_PASSWORD: borealis_password`, `POSTGRES_DB: borealis`,
    volume `borealis_pgdata`, healthcheck `-U borealis`, comment line.
12. Postgres only initializes user/db on an **empty** volume, so the rename
    requires a reset: `docker compose down && docker compose up -d postgres`
    (old `north_pgdata` volume can then be removed with `docker volume rm`).
    **This destroys all data** (accounts, chats, sources, chunks/embeddings).
    Acceptable for the local MVP: data is regenerable (re-upload
    `data/sample/*.csv` or re-run ingest; reports in `reports_storage/` and
    files in `uploads/` survive on disk but lose their DB rows). Update
    `server/.env` DATABASE_URL to match. If existing local data must be
    preserved instead, STOP and propose a pg_dump/ALTER-user migration.
13. Restart the full stack afterwards (python service, litellm, server, web)
    so every process picks up new names/keys; re-run
    `restoreDatasets()` implicitly via server boot (per AGENTS.md, server
    re-registers tabular sources on boot).
