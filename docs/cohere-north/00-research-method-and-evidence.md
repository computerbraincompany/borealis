# Research method, coverage, and evidence boundaries

**Point-in-time capture:** 2026-08-22<br>
**Starting site:** <https://private.docs.cohere.com><br>
**Purpose:** clean-room technical product documentation for an independent open-source implementation

## 1. Evidence hierarchy

This documentation uses evidence in the following order:

1. **Current first-party product/deployment/API documentation** under `private.docs.cohere.com`.[1][2]
2. **Published OpenAPI 3.1 contract** at `openapi/north.yaml`.[11]
3. **Official Cohere product pages and launch posts**.[5][6][7]
4. **Official public product demos**.[9][10]
5. **Credible external reporting** only for claims not exposed in product documentation, clearly attributed.
6. **Independent design proposals** for the open-source rebuild, always labeled as proposals rather than facts about Cohere internals.

Search-result snippets were not treated as page evidence. The source site advertises clean Markdown endpoints and a section-specific index; those were used as the primary machine-readable capture surface.[2]

## 2. Root-first and multi-method discovery

The root was inspected before secondary discovery. The crawl then used:

- root HTML/Markdown navigation;
- `robots.txt`;
- `sitemap.xml`;
- site-wide and North-specific `llms.txt` indexes;
- the raw OpenAPI JSON/YAML entry points;
- recursive internal links extracted from every successfully read page;
- retry variants: `.md`, `.mdx`, canonical HTML, and `/index.md`;
- two recursive rounds, stopping only after the second round found no new in-scope URL.

Compass Standalone, static assets, generic Cohere API documentation, and unrelated external sites were excluded from the exhaustive page count. North user guides, administration, security, deployment, vertical guides, changelog, and API/reference routes remained in scope.

## 6. Clean-room rules

- Recreate **documented behavior and interoperable contracts**, not private source code.
- Do not copy Cohere trademarks, logos, illustrations, icons, copywriting, or pixel-identical trade dress.
- Treat screenshots and vendor diagrams as attributed research only; do not ship them in the product.
- Label all inferred architecture and technology selection as an independent proposal.
- Do not claim an undocumented backend component, model prompt, database schema, retrieval algorithm, or ranking formula.
- Preserve public API interoperability only where legally appropriate; use project-owned names for internal modules and UI.
- Record provenance for every external claim and retain source dates/hashes.
- Security/compliance marketing statements are not equivalent to an audit report or certificate scope.

## 7. Knowledge limits

Public evidence is sufficient to specify most user workflows, object relationships, API resources, permission concepts, supported deployment dependencies, and operator responsibilities. It is insufficient to reconstruct exact prompts, model finetunes, ranking weights, chunking strategy, database schema, queue semantics, proprietary guardrail logic, evaluation datasets, analytics event payloads, or performance/SLO numbers not explicitly published. Those gaps are tracked in [`14-gaps-unknowns-and-clean-room-boundary.md`](14-gaps-unknowns-and-clean-room-boundary.md).
