## Test environment and repeatability

Use an isolated absolute workspace directory and, on desktop, the documented
absolute `--user-data-dir` profile. Never run destructive fixtures against the
user's `.borealis` or installed Borealis profile. Create all accounts/documents/
connections in disposable test workspaces. Do not print tokens, document text,
SQL results, provider errors, or real account data to logs. Store only synthetic
test artifacts and content-free summaries in committed verification evidence.

Install from repository root using Node 22.22.3 and pnpm 10.x:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm --filter borealis-server exec playwright install chromium
```

Add a scripted product acceptance harness under `scripts/e2e/` and synthetic

## Failure and lifecycle matrix

For relevant A–F journeys include selected-empty, wrong-account access,
deleted/unready inputs, stale mutations, pending/failed artifacts, truncated
legacy query receipts, duplicate submission and idempotent retries. Prove that
model/connection changes affect later operations while accepted turns retain
their declared snapshots and revocation still blocks future external calls.

Test timeout, cancellation during extraction/tool execution/rendering, provider
unavailability, malformed tool results and insufficient source evidence. UI
navigation/reload and closed dialogs must not leak stale success/errors. A failed
folder/WebDAV refresh cannot silently become a fresh recurring brief. Exercise
research recovery after process interruption without duplicate cells/artifacts;
never automatically replay external side effects after a crash.

Test timezone and DST spring/fall transitions, app closed across due time,
overlapping recipe invocations, missing target, review conflicts, ignored
notifications, and orderly quit during every kind of background work. Prove
the backend acknowledges shutdown only after workers, MCP children and store
handles have drained. Check no process/profile lock is leaked after each run.

Upgrade a populated schema-v13 fixture through real v14–v16 and all product
migrations. Preserve old agents/skills, chats, sources, report shares and
artifacts. Run same- and changed-dimension live embedding migrations with new
artifact types present. Archive/restore a stopped populated workspace containing
every new durable object; verify complete metadata/content and indexes, and
explicit reconnect/reselect state for nonportable credentials/folder grants.
Preserve old work even when historical source generations no longer exist.

## Export and packaging checks

Verify HTML is self-contained, PDF begins `%PDF-`, chart PNG has valid PNG magic,
DOCX is a readable ZIP/OOXML document, Markdown retains readable evidence, and
CSV/XLSX (where specified) retains typed values and formula-safe exports.
Inspect rendered PDF pages and the opened DOCX visually for clipped text,
missing charts, broken tables and citation appendix layout. Do not count a file
extension or status 200 as proof of a usable export.

Build fresh production artifacts and execute these **existing** gates from root:

```bash
pnpm verify
pnpm --filter borealis-desktop verify
pnpm package:unsigned
pnpm --filter borealis-desktop package:native:smoke
pnpm --filter borealis-desktop package:entitlements:smoke
```

All must exit zero. `pnpm verify` must print `ALL GATES GREEN`; it does not
replace GUI render smoke, packaging or live-model acceptance. Then execute all
three new product E2E commands. Capture content-free counts, final commit,
platform/runtime versions, check timestamps and fixture identifiers. Rebuild
after source changes so desktop testing never validates stale copied runtime.

Do not require signing/notarization credentials or a commercial cloud account
for this wave. Actual Apple Silicon macOS, graphical UI permission and a local
tool-capable chat/embedding pair are required for final desktop/live checks.
If unavailable, keep those cells NOT RUN/BLOCKED; do not redefine DONE.
